Docs

SweetVibe is a music player for the terminal. Everything on this page is checked against the source — the command and keybinding tables are the real ones the player accepts.

Installation

Press Download in the header and run the installer. It installs wherever you point it, and there is nothing else to do — no FFmpeg, no bundled tools.

Running from source

git clone https://github.com/RandomCatUser/SweetVibe
cd SweetVibe
pip install -r requirements.txt
python main.py

Music Library

SweetVibe reads audio from the songs/ folder next to main.py. Drop files in and they appear.

Press Tab to switch to PC-Scan, which walks your home directory and every drive except C: and builds a library of everything it finds. Tab again returns to Browse. The scan runs on a background thread and logs what it finds.

Accepted formats are mp3, wav, flac, m4a, ogg, opus, aac and webm. CJK titles render at the correct width, so Japanese and Chinese libraries line up instead of drifting.

Playlists

Playlists are saved to ~/.sweetvibe_playlists.json. They store item names and paths rather than copies of the audio, so a playlist keeps working as long as the files are still there.

  • save stores the queue exactly as it is right now.
  • load appends, so you can build up a queue across several playlists.
  • play replaces the queue and starts at the first track.
  • view shows the contents without touching the queue.

Loading a playlist whose files have moved reports the missing tracks and plays the rest.

YouTube

:yt <query> opens a search panel. Move with ↑ ↓, press Enter to download and queue, Ctrl+B to dismiss.

Where files go

Downloads follow the folder you are browsing. If you would rather pin one, :cache dir <path> sets it and :cache info shows what is currently in effect.

A fetched track is cached by URL, so the second play is instant. The cache maps URLs to files on disk; clearing it does not remove music you downloaded deliberately.

Formats and playability

YouTube serves WebM/Opus, which the audio engine cannot decode directly. The plugin picks a stream it can play, rewrites WebM to Ogg Opus in pure Python — no FFmpeg, no re-encoding — and deletes the source. One download leaves exactly one playable file.

Downloads run with retries and a stall watchdog, and the progress bar shows percentage, size, speed and ETA. If a track cannot be fetched, the reason is logged to ~/.sweetvibe_cache/last_download_error.txt.

Requirements

yt-dlp is imported as a Python library. There is no yt-dlp.exe anywhere in the install, and the release contains exactly one executable. 

pip install -U yt-dlp

Without it, everything else keeps working and :yt reports that it is missing.

Spectrum

Three modes:

ModeBehaviour
autoDriven by a timer. Works with no extra packages.
reactiveDriven by the live audio stream. Needs numpy and soundfile.
scriptYou supply the bar values yourself.

Bar colours are set by name in custom_colors (color_1 to color_5) and mapped through COLOR_MAP in main.py, so any of the 16 terminal colours works. Change them from :settings.

Plugins

Every .py file in plugins/ is loaded at startup, in alphabetical order. If the module has a setup(player) function it is called with the player. Everything else is optional, and a plugin that raises on import is logged and skipped rather than taking the player down with it.

Hooks

Append a callable to player.plugin_hooks. All seven exist from the start.

HookSignatureCalled
on_command(cmd, raw_text)Per command-bar entry. Return True to consume it.
on_key(key_str, action)Per keypress. Return True to consume it.
on_play_request(item)Before playback. Return True to take over.
on_play(filepath)A local track started.
on_stop()Playback stopped.
on_draw(screen)Every frame, over the player.
on_tick()Every frame. Keep it cheap.

Example: a command

The smallest useful plugin. :shuffle reports the current mode and flips it. 

def setup(player):
    player.plugin_hooks["on_command"].append(on_command)

def on_command(cmd, raw_text):
    if cmd != ":shuffle":
        return False
    player.shuffle = not player.shuffle
    player.add_log("Shuffle " + ("on" if player.shuffle else "off"))
    return True

Return False for commands you do not handle. Returning True unconditionally swallows every other plugin's commands.

Example: react to playback

on_play fires with the Path of the track that just started; on_stop fires when playback ends. 

import time

_started = {}

def setup(player):
    player.plugin_hooks["on_play"].append(on_play)
    player.plugin_hooks["on_stop"].append(on_stop)

def on_play(filepath):
    _started[filepath] = time.time()
    meta = player.metadata or {}
    title = meta.get("title") or filepath.stem
    player.add_log("Now playing: " + title)

def on_stop():
    for path, at in list(_started.items()):
        player.add_log("Played %d s of %s" % (time.time() - at, path.stem))
    _started.clear()
player is not a global. setup(player) receives it, so bind it to a module-level name if your callbacks need it later. Forgetting that is the most common reason a plugin logs nothing at all.

Example: state that changes over time

Advance state in on_tick and paint in on_draw. Throttle on the wall clock rather than counting frames, because the frame rate is not guaranteed. 

import time

_state = {"last": 0.0, "text": ""}

def setup(player):
    player.plugin_hooks["on_tick"].append(on_tick)
    player.plugin_hooks["on_draw"].append(on_draw)

def on_tick():
    now = time.time()
    if now - _state["last"] < 1.0:
        return
    _state["last"] = now
    _state["text"] = time.strftime("%H:%M:%S")

def on_draw(screen):
    from asciimatics.screen import Screen
    if not _state["text"] or screen.width < 20:
        return
    screen.print_at(
        " " + _state["text"] + " ",
        screen.width - 12, screen.height - 1,
        Screen.COLOUR_GREEN, Screen.A_BOLD, bg=Screen.COLOUR_BLACK)

on_tick runs every frame. Anything expensive belongs on a thread, not here.

Drawing safely

on_draw paints over the player, so clip to the screen or the renderer will raise. 

def on_draw(screen):
    from asciimatics.screen import Screen
    w = screen.width
    if w < 20:
        return                      # too narrow: skip rather than crash
    player.draw_box(4, 3, min(46, w - 8), 7,
                    " now playing ", Screen.COLOUR_MAGENTA,
                    rounded=True, bg=Screen.COLOUR_BLACK)

These helpers already account for wide characters:

HelperGives you
player.get_display_width(t)Width counting CJK glyphs as two columns.
player.truncate_text(t, w)Text clipped to a display width, with an ellipsis.
player.pad_text(t, w)Text padded to an exact display width.
player.draw_box(...)A framed panel, the way the bundled plugins make theirs.

Use only the 16 asciimatics colour constants (Screen.COLOUR_BLUE and friends). An out-of-range numeric colour index raises during rendering.

Example: resolving an online item

To queue something your plugin resolves itself, use ("online", name, url, 0) and handle it in on_play_request. 

import threading

def on_play_request(item):
    if item[0] != "online":
        return False
    name, url = item[1], item[2]
    player.add_log("Fetching " + name)
    threading.Thread(target=resolve, args=(url,), daemon=True).start()
    return True

def resolve(url):
    # slow work goes here
    ...

on_play_request is called from the main loop. Blocking in it freezes the whole interface, so hand slow work to a thread.

When a plugin misbehaves

A plugin that raises during setup is caught and reported as Plugin err <name>, and the player carries on. Exceptions raised later, inside a hook, are not caught for you: 

def on_command(cmd, raw_text):
    try:
        return handle(cmd, raw_text)
    except Exception as exc:
        player.add_log("myplugin: " + str(exc)[:40])
        return False

Updates

:update asks GitHub for the newest release and shows a modal with the version and the install button. Versions are compared numerically per dot-part, so 1.10 correctly sorts above 1.9.

Dismissing a release records it in ~/.sweetvibe_skipped_version so it will not ask again on every launch. Clearing that file, or using :update explicitly, checks anyway.

Building

You need Python, PyInstaller and Inno Setup 6.

pip install -r requirements.txt pyinstaller
pip install -U yt-dlp
.\build.ps1

That runs pyinstaller main.spec and then compiles setup.iss. Output lands in dist\SweetVibe\ and dist\installer\Setup_Windows_x64.exe.

Versioning

The version appears in three places and they must agree:

FileKey
main.pyCURRENT_VERSION
version_info.txtfilevers, prodvers, and the two version strings.
setup.issMyAppVersion

version_info.txt has both a numeric tuple and a display string. Set both, or Windows will report two different versions.

Continuous integration

.github/workflows/build.yml does this on every push. It also fails the build if any executable other than SweetVibe.exe ends up in the output, which is what keeps the yt-dlp change honest. Tagging a version, for example git tag 1.6.0, publishes the installer to a GitHub release using the notes in .github/release-notes.md.

Troubleshooting

A track will not play

The engine decodes mp3, ogg, opus, wav and flac. Files in other containers get remuxed where possible, including when they come from a browse list or an old download. Play it again to trigger the repair, and if it still fails the format is unsupported.

YouTube does nothing

Check that pip show yt-dlp finds something. The player prints a setup hint on the log line if the module is missing.

Downloads went somewhere unexpected

They follow the folder you are browsing. :cache info shows the effective target and :cache dir <path> overrides it.

Antivirus flags the installer

A known false positive on unsigned Python bundles. The build produces a single executable with no third-party binaries, so compare the hash against the release, or add an exclusion for the file.

Everything looks cramped

SweetVibe wants roughly 80×24 or better. Widen the terminal or reduce the font size. Wide CJK glyphs are measured as two columns, so those titles align correctly rather than overflowing.
