SweetVibe Docs

SweetVibe is a fast, keyboard-driven music player for the terminal. This is everything you need to use it, extend it and build it from source.

Quick Start

Install SweetVibe and start playing. The installer is a single signed download; zero configuration required.

Installation

Ready-to-run installers for Windows. Use the Download button in the top bar, or build from source if you would rather.

Build from Source

Running from source

git clone https://github.com/RandomCatUser/SweetVibe cd SweetVibe python -m pip install -r requirements.txt python main.py

Required packages are asciimatics, tinytag and just_playback — the player exits with a clear message if any are missing. numpy and soundfile are optional and only enable the reactive spectrum. Music is read from the bundled songs/ folder.

Keybindings

:settings opens the editor. Bind a key with Enter, remove one with Backspace, press R to restore defaults. Your bindings are stored as plain text in ~/.sweetvibe_keybinds, so they survive reinstalls and you can edit that file by hand.

YouTube

:yt <query> opens a search panel. Results are sanitised to plain ASCII so nothing can break the layout, then Enter queues a track and downloads it in the background with live progress.

Downloads follow the folder you are browsing, or the folder pinned with :cache dir. Once fetched, a track is cached forever and replays instantly.

Under the hood. The online plugin imports yt-dlp as an ordinary Python library. No yt-dlp.exe is downloaded, shipped or executed — the release contains exactly one executable, SweetVibe.exe. Progress comes from yt-dlp's progress hooks and the finished path from prepare_filename(), so there is no subprocess and no console window.

yt-dlp is optional. If the package is missing the player logs a short message and keeps working. Install it with python -m pip install -U yt-dlp.

YouTube streams arrive as WebM/Opus or M4A/AAC, which the audio engine cannot decode directly. The plugin remuxes WebM/Opus to Ogg Opus in pure Python — no FFmpeg, no re-encoding — then deletes the source, so a download leaves exactly one playable file.

Plugin Development

Any .py file in plugins/ is loaded at startup. If it defines setup(player), that function is called with the player object. Everything else is optional.

def setup(the_player): global player player = the_player player.plugin_hooks["on_command"].append(my_command) player.plugin_hooks["on_draw"].append(my_draw) def my_command(cmd, raw_text): if cmd == ":hello": player.add_log("Hello from my plugin!") return True # True = handled, stop looking return False def my_draw(screen): from asciimatics.screen import Screen screen.print_at(" hi ", 2, 0, Screen.COLOUR_CYAN, Screen.A_BOLD)

Hooks

HookCalled
on_command(cmd, raw_text)For each command-bar entry.
on_key(key_str, action)For each key press.
on_play_request(item)Before playback; return True to take over.
on_play(filepath)When a local track starts.
on_stop()When playback stops.
on_draw(screen)Every frame, on top of the player UI.
on_tick()Every frame. Good for animation state.

Non-file items

Queue items are 4-tuples. Local tracks are ("file", name, Path, duration). To inject something your plugin resolves itself — a stream, a remote track — use ("online", name, url, duration) and handle it in on_play_request, returning True once you have taken it on.

Bundled plugins: online.py, lyrics.py, albumart.py, girl.py, meow.py.

Spectrum & Colors

Three visualizer modes are available:

  • Automatic — pure timer, works without numpy.
  • Reactive — driven by the live audio stream. Needs numpy and soundfile.
  • Script — you supply the bar values yourself.

Bar colours are set by name and mapped through COLOR_MAP in main.py, so any of the 16 terminal colours works. The five defaults live in DEFAULT_COLORS.

Architecture

The whole player is a single file, main.py:

PartWhat lives there
ImportsCore dependency checks and optional extras.
ConstantsAUDIO_EXTS, COLOR_MAP, DEFAULT_KEYBINDS.
HelpersUpdate checks, formatting, path resolution.
KityPlayerAll state: playback, navigation, scanning, drawing.
demo()Builds the asciimatics Screen and runs the loop.

Plugins never import main.py. They receive the player object and read player.screen, player.display_playlist and the rest of the public API from it.

Building

You need Python with the dependencies installed, PyInstaller, and Inno Setup 6.

python -m pip install -r requirements.txt pyinstaller python -m pip install --upgrade yt-dlp .\build.ps1

That runs pyinstaller main.spec and then compiles setup.iss. Output lands in dist\SweetVibe\ and dist\installer\.

main.spec collects asciimatics, tinytag, just_playback and the yt_dlp package, then bundles the songs/ and plugins/ folders. Because yt-dlp is collected as a package rather than an executable, the release ships a single .exe — which also keeps antivirus false positives away.

Bump the version in main.py, version_info.txt and setup.iss together.

Troubleshooting

“yt-dlp module missing”

Run python -m pip install -U yt-dlp. Everything else keeps working without it.

A track will not play, or stops immediately

The audio engine decodes mp3, ogg, opus, wav and flac. If a file uses some other container the player says so and remuxes it when it can — try the track again, or pick a different search result.

A download is not where I expect it

:cache dir <path> pins the target. :cache info shows the current one.

Antivirus flags the installer

Unsigned Python bundles are a known false positive. Confirm you built it yourself from source, or add an exclusion. The build no longer bundles any third-party executable.

The terminal looks cramped

SweetVibe needs roughly 80×24 or better. Widen the window or reduce the font size.
