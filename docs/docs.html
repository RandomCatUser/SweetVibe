Docs

How to run SweetVibe, drive it from the keyboard, and add your own plugin. Longer references live in the repo under docs/.

Install

Press Download in the header and run the installer. It puts SweetVibe wherever you point it, and you are done.

Or run it from source:

git clone https://github.com/RandomCatUser/SweetVibe
cd SweetVibe
pip install -r requirements.txt
python main.py

Music comes from the songs/ folder next to main.py. Drop files in, or press Tab in the player to scan your drives.

Commands

Hit : and type one of these.

CommandDoes
:settingsKeybinding editor.
:updateCheck for a new release.
:yt <query>Search YouTube. Enter on a result downloads it.
:pl listList playlists.
:pl save <name>Save the current queue.
:pl load <name>Append to the queue.
:pl play <name>Replace the queue and play it.
:pl del <name>Delete a playlist.
:cache infoShow the download folder and cache size.
:cache dir <path>Pin where downloads go.
:cache clearEmpty the cache. Your music files are not touched.
:cache openOpen the download folder.
:girlDancing girl. Add fast or slow.
:meowDancing cat.
:lyricsScroll lyrics for the current track.
:artSave embedded album art as a PNG.

Ctrl+B or Esc closes whatever is open.

YouTube

:yt <query> opens a search panel. Enter on a result downloads it and queues it. Downloads land in the folder you are browsing, unless you pinned one with :cache dir.

A track is fetched once and cached from then on, so replays are instant.

YouTube serves WebM/Opus, which the player cannot decode directly. The plugin rewrites it to Ogg Opus in pure Python and deletes the original, so one download leaves exactly one file.

yt-dlp is imported as a library — there is no yt-dlp.exe anywhere in the install. If you are missing it: 

pip install -U yt-dlp

The rest of the player works without it.

Plugins

Any .py file in plugins/ is loaded at startup. If it has a setup(player) function, that gets called with the player. Everything else is optional. 

def setup(player):
    player.plugin_hooks["on_command"].append(my_command)

def my_command(cmd, raw_text):
    if cmd == ":hello":
        player.add_log("hi")
        return True      # handled — stop here
    return False

Hooks

HookWhen
on_command(cmd, raw)Every command-bar entry.
on_key(key, action)Every keypress.
on_play_request(item)Before playback. Return True to take over.
on_play(path)A local track started.
on_stop()Playback stopped.
on_draw(screen)Every frame, over the player UI.
on_tick()Every frame. Use for animation state.

Drawing

def my_draw(screen):
    from asciimatics.screen import Screen
    screen.print_at(" hi ", 2, 0, Screen.COLOUR_CYAN, Screen.A_BOLD)

Queue items

Items are 4-tuples. Local tracks are ("file", name, path, seconds). To add something your plugin resolves itself, use ("online", name, url, seconds) and handle it in on_play_request.

Bundled: online, lyrics, albumart, girl, meow.

The complete API is in docs/plugins.md.

Building

Needs Python, PyInstaller and Inno Setup 6.

pip install -r requirements.txt pyinstaller
pip install -U yt-dlp
.\build.ps1

That runs pyinstaller main.spec then compiles setup.iss. Output: dist\SweetVibe\ and dist\installer\.

The version lives in three places — main.py, version_info.txt and setup.iss. Bump all three.

A GitHub Actions workflow does this automatically and tags a release for you: .github/workflows/build.yml.

Troubleshooting

A track will not play

The engine decodes mp3, ogg, opus, wav and flac. Other containers get remuxed when possible — try the track again, or pick a different search result.

Downloads went somewhere unexpected

:cache info shows the current folder. :cache dir <path> changes it.

Antivirus flags the installer

Common false positive on unsigned Python bundles. The build ships a single executable, so there is no third-party binary to explain — verify the hash against the release, or add an exclusion.

Everything looks cramped

SweetVibe wants about 80×24. Widen the terminal or drop the font size.
